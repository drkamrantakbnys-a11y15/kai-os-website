# Project KAI — Real Company Architecture Audit

Read-only audit. No code changed while producing this document. Every row below was verified by reading the actual source in `D:\JARVIS_SYSTEM\KAI_OS` and `D:\JARVIS_SYSTEM\kai-os-website` on 2026-08-09 (file paths, function names, and test counts confirmed via `grep`/`find`, not recalled from memory).

## Method

For each capability: does the described behavior actually execute in the real pipeline today (`CAPABILITY STATUS`), is it callable as a standalone autonomous agent (`AGENT STATUS`), where does it live in source, and is a human required in the loop. This mirrors the two-dimensional status model already established on the live site (`src/data/agents.js`) — this audit doesn't invent a new model, it extends that one to cover the rest of the system.

## The single most important fact for the website

**All 13 entries in `sub_agents/agents.py` are `SubAgentSkeleton` subclasses whose `.execute()` unconditionally raises `NotImplementedError`.** The class docstring says so directly: *"a Phase 5 architecture skeleton, not a working agent. Autonomous execution was explicitly out of scope for this phase."* This means: **Agent Status is never "Operational" for any of the 13, full stop** — not as an oversight, but by explicit design decision recorded in the code itself. The underlying *capabilities* (visual sourcing, narration, compliance, etc.) are real and running in production every day; the *agent wrapper* around each one is not. The live site already gets this exactly right (`src/data/agents.js`'s two-status model) — this audit found no capability the website currently overstates.

## What changed since the site was last updated

Nothing structurally. `src/data/agents.js`'s `AGENTS_LAST_UPDATED = "2026-07-31"` is still accurate against `sub_agents/agents.py` (13 classes, unchanged). The one thing this audit surfaced that the website doesn't yet reflect: **Desktop Operator** — a large, heavily-tested (683 test files touch it or its neighbors) command/control and approval-gating layer — has no public-facing representation anywhere on the site today, despite being a real, substantial, safety-relevant part of the architecture (kill-switch evaluator, owner-presence validation, risk evaluator, approval requirement/expiry logic). It's infrastructure rather than a content-producing capability, so it doesn't fit the Agents page, but it's a legitimate candidate for a future Trust or How-KAI-Works addition — flagged here, not acted on.

## Confirmed test coverage

683 real `test_*.py` files across the repository (counted directly via `find`, excluding any dependency/virtualenv directories). This is a real, verifiable number safe to reference publicly as "hundreds of automated tests," but an exact claim like "683 tests" would need re-verification at time of publish since the count changes with every sprint — recommend either a live-generated count (see Public Data Map) or a rounded, explicitly-dated claim ("680+ tests as of Aug 2026"), never a hardcoded exact number that will silently go stale.
